# A 30-minute ToneScope tour

This guide describes the development build. Planned production features are identified explicitly. Use a short mono/stereo WAV you own; synthetic fixtures generated by `evals/oracles.py` are reproducible but are not a licensed guitar listening corpus.

1. **5 minutes: signal flow.** Read `libs/audio-engine/include/tonescope/Engine.h`, then `libs/audio-engine/src/Engine.cpp`. The engine sanitizes ingress, smooths numerical controls, runs an ordered chain and writes output. UI rendering and audio callbacks have different ownership.
2. **5 minutes: authored versus generated.** Read `dsp/faust/drive.dsp`, then its generated `dsp/generated/ToneScopeDrive.h` and hash manifest. The compressor, EQ coefficient design/biquads and waveshaper execute generated Faust kernels; host control scheduling, crossover/FIR and surrounding drive filters remain C++. See `docs/dsp/faust-stages.md`. Never edit generated output manually.
3. **10 minutes: microscope.** Import audio, leave effects bypassed and compare dry/processed. Enable drive, freeze RMS match, select a passage and listen to the residual. Read `libs/analysis/src/Analysis.cpp`: RMS matching and subtraction have precise, limited meanings.
4. **5 minutes: evidence.** Run contracts and integration suites, inspect `run.json` and HTML report. Follow hashes to actual files. Look at blocked qualification, not just passing cases.
5. **5 minutes: ownership.** Trace UI controls through the fixed snapshot queue to the processing thread. Follow background render revision checks. Read `delivery/brain.md` to see what remains.

## Ten experiments

| Experiment | Prediction and control | Audible result and measurement | Code and limitation |
|---|---|---|---|
| Samples and dBFS | Increase output by 6 dB | Approximately twice the sample amplitude before guarding; RMS rises 6 dB | `Engine.cpp` gain conversion; sample peak is not true peak |
| Filters and phase | Set mid EQ +6 dB, play 1 kHz sine | Center grows; measure steady RMS ratio | Native bell test; FFT magnitude does not describe phase |
| Compressor curve | Threshold -18, ratio 4, long steady input above threshold | Output grows more slowly; measure gain reduction after settling | Independent `compressor_gain_db` oracle; no hidden auto makeup |
| Attack/release | Lengthen attack, then release on stepped audio | Transients pass differently; inspect measured envelope and GR timeline | Detector has fixed 10 ms power integration plus gain smoothing; independent numerical crossing gates pass, while device/listening qualification remains open |
| Harmonics | Enable drive on a clean sine | Additional harmonics and changed timbre | Faust `tanh` stage; nonlinear output is level dependent |
| Aliasing | Sweep a high-frequency sine with drive | Folded components may appear | Compare 1x/2x/4x drive; the independent fixed alias fixtures pass, while musical preference still needs listening |
| Latency/buffering | Change device buffer while stopped | Responsiveness/dropout tradeoff depends on device | Device buffer frames/rate is a period, not loopback latency; hardware test required |
| Residual | Compare unity, then apply a known gain | Unity nulls; gain difference leaves source-shaped residual | `compare`; residual is mathematical difference, not isolated added harmonics |
| Real-time ownership | Queue rapid parameter changes | Audio should continue while UI updates | Fixed snapshots/noexcept setter; allocation tests do not qualify device timing |
| Grounded tools | Inspect release validator and proposed assistant boundary | The optional service uses actual measured previews and explicit acceptance | Offline rules are a bounded baseline; live model quality remains unqualified |

For each experiment record your prediction before listening, one control change, before/after audio, numeric result and a limitation. Do not score monitor guard or loop-boundary fades as DSP behavior.

## Two small modifications

- Change the fixed low shelf frequency from 120 Hz to 160 Hz. First add an independent expected-response case, modify the design, then rerun native and numerical tests. Explain why center/transition behavior changes.
- Add a named parameter to the registry. Update native validation, schema and UI together, then add out-of-range/nonfinite contract cases. Confirm old sessions retain an explicit default and never bypass validation.

Human listening, Narrator/scaling effectiveness, interface timing and musical usefulness need actual participants/devices; this guide is an experiment protocol, not their results.
