# Optional ToneScope assistant

This separately gated D3 service runs offline by default. Its deterministic rules baseline supports bounded level changes. It reads native measurements, renders a candidate using the actual native CLI, compares it, and returns a revision/hash-bound B.3 proposal. No service or tool applies changes. The native application owns explicit acceptance, stale/hash checks, preview audition, and the single undo transaction. Core audio works when this optional service is absent.

Offline host startup validates live configuration with the lightweight Zod schema in `live-policy.ts`; it does not load the live provider SDK. The host loads that SDK only after explicit live-mode configuration and credentials pass their existing checks. Native startup retains its eight-second handshake budget. Bounded native failure messages distinguish preparation, startup and HTTP/transport errors without exposing arbitrary exception details. UI smoke checks fail immediately on a terminal assistant error while retaining the original verified-proposal assertion and deadline. These diagnostics do not establish the cause of a historical intermittent failure.

Node 24 and the exact dependencies in package-lock.json are required. Use `npm ci`, `npm run typecheck`, `npm test`, and `npm run build` in this directory. The build compiles all five Eve tools and an inert deny sandbox provider to `.output`; it performs no deployment or model calls. The broker entry is `node --experimental-strip-types agent/lib/host.ts` (`npm start`). A private host manifest and a bearer capability of at least 32 bytes must be provided through `TONESCOPE_HOST_MANIFEST` and `TONESCOPE_BROKER_TOKEN`. Neither belongs in a webview, repository, URL, or log.

The manifest is private native-host configuration, not model input:

```json
{"executable":"ABSOLUTE_NATIVE_CLI","work_directory":"ABSOLUTE_PRIVATE_PREVIEW_DIR","state_directory":"ABSOLUTE_PRIVATE_HISTORY_DIR","port":0,"assets":[{"snapshot":{"session_id":"session_1","session_revision":1,"source_sha256":"64_lowercase_hex","base_graph_sha256":"64_lowercase_hex","source_handle":"opaque_asset_1","selection_samples":[0,48000],"sample_rate":48000,"parameters":[{"stage_id":"output","parameter_id":"outputDb","unit":"dB","value":0,"min":-24,"max":24}]},"source_path":"ABSOLUTE_HOST_SELECTED_WAV","baseline_path":"ABSOLUTE_NATIVE_BASELINE_WAV","parameters":{"outputDb":0}}]}
```

`parameters` is the full native engine session parameter object, including enabled stages, order and modes, supplied by the host. `snapshot.parameters` is its authorized continuous-control registry. Paths are resolved only from this private registry. Baseline WAV plus its native `.wav.json` sidecar must represent this revision's graph, original source digest and exact selection. Source and baseline digests are rechecked; registry assets are reread for every operation. A modern native CLI selection baseline carries `selection_samples`, `processed_frames`, and `alignment_samples`. Legacy full-source baseline manifests remain supported. Cropped candidates process from sample zero with matching history, then compare the local cropped buffers.

The service listens on IPv4 loopback and prints its selected port for a manual host, or publishes an atomic private ready file for the native client. Every route requires `Authorization: Bearer TOKEN`. Any Origin header is rejected. The token stays in the native host; the webview calls native commands. Endpoints:

- `POST /v1/request`: `{schema_version:1,request_id,session_id,prompt}`; returns the exact B.3 envelope. Request IDs are unique; never reuse them after failure/cancellation.
- `GET /v1/requests/REQUEST?session_id=SESSION`: redacted persisted result, or 404.
- `POST /v1/requests/REQUEST/cancel?session_id=SESSION`: body `{}`; cancellation is session-scoped and rejects late results.
- `DELETE /v1/session?session_id=SESSION`: deletes history and known preview files, cancels active work, and tombstones the session in this process.

The preview ID identifies `work_directory/PREVIEW_ID/preview.wav` for trusted native audition. Native code must rehash this WAV against `preview.audio_sha256` immediately before audition/apply. No file path is returned to the model. The host should rotate session IDs and restart its broker when opening a different project; the startup authorized-session set cannot expand through requests.

For the real native synthetic test, set `TONESCOPE_TEST_CLI` to the local native renderer executable before `npm test`. Without it, that test is explicitly skipped. Test fixtures verify protocol/security only. They are not listening, hardware, DSP qualification, or live-model evidence. Independent evaluator probes measure actual WAV output separately.

See [tool card](../../docs/assistant/tool-card.md), [model card](../../docs/assistant/model-card.md), and [data card](../../docs/assistant/data-card.md).

Live experiment execution has a separate private consent contract in `agent/lib/live-policy.ts`. Its strict version-one schema binds the experiment and budget IDs, frozen protocol/task/schedule/admissions SHA256 values, exact model/provider, selected-endpoint metadata digest, verified UTC timestamp (at most 24 hours old), per-million-token input/output rate ceilings, USD ceiling, request/generation ceilings, fixed protocol limits, and all four approved data classes. The classes are `request_text`, `scalar_measurements`, `authorized_controls`, and `identity_metadata` in that order. Identity metadata includes session/revision/source/graph/selection IDs. Credentials are never accepted in consent or request JSON. Normal native env-file launch remains offline.

`agent/lib/live-collector.ts` is a separate opt-in entry point. Offline evaluation/replay runners do not import it. `node --experimental-strip-types agent/lib/live-collector.ts --preflight --consent-file PRIVATE_JSON` validates consent and returns `{consent_sha256,normalized_policy,protocol_sha256,task_sha256,schedule_sha256}` without credentials, SDK loading, network access or dispatch. Use this digest in other languages: it is recursively sorted-key compact UTF-8 JSON with JavaScript number serialization and no newline. To execute an explicitly authorized frozen experiment, use `--run-consented-experiment --consent-file PRIVATE_JSON --manifest-file PRIVATE_JSON` instead. This development task does not authorize that operation. The collector manifest uses the same executable/work/state/assets fields as the host manifest, without `port` or `live`, and requires `admissions:[{request_id,prompt_sha256,role}]` for the complete frozen schedule. JSON stdin is `{schema_version:1,consent_sha256,protocol_sha256,task_sha256,schedule_sha256,request:{schema_version:1,request_id,session_id,prompt}}`. The output is `{schema_version:1,request_sha256,result,private_preview_path?}`. The artifact path is private collector transport metadata and never appears in model context or exported trace. Each scheduled attempt uses its request ID as its attempt ID. There are no provider retries or model/provider fallbacks.

`live-admission.ts` exports `admissionsSchema`, `normalizeAdmissions`, `admissionsDigest`, `promptDigest` and `AdmissionGuard`. The complete allowlist has unique request IDs and at most 168 scored, six setup and six lifecycle entries; its digest sorts entries by ASCII request ID before canonical JSON serialization. Prompt hashes cover the exact raw UTF-8 prompt. `new AdmissionGuard(fullList,['lifecycle'])` admits only the host lifecycle slots while retaining the same complete-list digest. The service requires this guard as constructor argument seven for all live providers; there is no permissive fallback. The collector restricts roles to scored/setup. Missing IDs, changed prompt hashes, role borrowing and changed manifest digests fail before reservation or metadata/provider calls. Session IDs may be assigned at runtime, then the ledger binds the actual complete request and prevents request-ID reuse across sessions.

Before a billable generation, the production adapter validates fresh catalog identity and the exact selected provider endpoint from the [Gateway REST endpoint API](https://vercel.com/docs/ai-gateway/sdks-and-apis/rest-api#get-model-endpoints). `gateway-metadata.ts` exports the canonical metadata projection and digest helper. It requires one active selected endpoint, explicit text/structured-output/token-limit capabilities and explicit base/cache/tier prices. Missing, changed or unknown pricing fails closed. Every selected base/cache/tier rate must fit the consent ceiling; cheap generic catalog pricing cannot authorize a more expensive provider. The digest excludes volatile uptime/latency fields. Provider and service consent digests must match. Injectable models/transports always label results `fault-injected`; they cannot produce live qualification.

`budget-v2.json` is the separate durable accounting ledger. The host must preserve its directory for the entire budget lifetime. A request reservation atomically consumes one lifetime slot, currency, and a process-owned concurrency admission. Request IDs are globally unique within the budget; changing a session cannot reuse them. Identical reserve replay does not charge twice and never grants dispatch. Every generation consumes a persisted slot before invocation. Identical terminal settlement is idempotent; conflicting usage is rejected. Unknown, canceled and interrupted work keeps the full request reserve and consumed slots. History deletion/pruning does not delete accounting tombstones. Fixed budget/consent identity, ceilings, record keys, counts, phases and balances are checked on each transaction. Existing legacy `budget.json`, malformed ledgers and changed consent fail closed; migration/refunds require separate review. Atomic replacement and file sync establish process-kill recovery only, not power-loss durability. A bounded sharing-error retry repeats only the same closed temporary-file rename while retaining the budget lock; it never unlinks the destination, changes the payload or repeats provider work. Permanent or exhausted storage failures remain failures.

Durable concurrency permits two requests globally and one per session across brokers. Transactions wait at most about one second for a live lock owner; contention never steals a live/PID-reused owner. A dead request owner releases only concurrency, retaining its spend and tombstone. A dead lock fails closed. After stopping all brokers and verifying the recorded PID is dead, an operator can call `new LiveLedger(directory).recoverDeadLock(expected_nonce)`; it rejects a live PID or changed nonce. An empty/invalid lock from death before owner publication cannot establish death and needs explicit operator review, with the existing ledger/reservations preserved. No automatic deletion, refund or retry occurs. If storage remains unavailable, durable cleanup cannot be promised; native preview and in-memory cleanup still run, and a later process can release established dead admissions without refunding funds.

A live result adds `authorization`, bounded `snapshots`, and `trace` fields. Authorization binds experiment/budget/consent/protocol/task/schedule identity, provenance, reserved currency, and whether usage is authoritative. The ordered trace binds the same experiment/request/attempt/session, uses monotonic event sequence numbers and includes only allowlisted numeric/hash/control identities. It covers admission, reserve, generation start/end, snapshot/measurements, render/compare, verified preview and terminal status; available provider response IDs are bounded and included. The native host can append acceptance/apply/undo to this same trace. Snapshot records are bounded authorized-control context, not full native graphs or audio qualification. Native integration must separately retain complete before/candidate/after/undo parameter graphs. The response stays within the existing 64 KiB native limit. Terminal usage and trace are detached from mutable provider state; late providers cannot change them. Cancellation is registered before history loading. Preview/admission cleanup also runs after settlement/history failure.

`test/live-recovery.test.ts` uses real subprocess brokers, the installed Gateway wire adapter plus `generateText`, controlled zero-cost fetch responses and the actual native CLI. It kills processes at twelve barriers with three repeats each, then tests durable replay/history deletion, owner locks, two-session concurrency and request/generation/currency ceilings across contention/restart. Set `TONESCOPE_TEST_CLI` to require the actual renderer and `TONESCOPE_P2_EVIDENCE` to an ignored evidence folder. The controlled transport cannot access provider networking and all records are `fault-injected`. These tests do not qualify live-model, listening, hardware or power-loss behavior.

The desktop bridge discovers `assistant/host.mjs` beside the executable first, then the pinned development service. Node 24 and the native CLI must be installed or bundled. It creates an OS-random bearer, owner-protected private registry/env/ready files, and a random loopback port. The native env-file handshake forces offline rules even if the launching shell contains provider credentials. Network/process work runs on dedicated workers. Missing optional components produce an unavailable message while normal audio continues.

For a streaming selection not fully covered by the native audio cache, the host may replace `baseline_path` with `baseline_metrics:{rms,peak,alignment_samples,binding}`. RMS and peak are finite nonnegative linear amplitudes measured over the exact raw full-band processed selection. `binding` contains session_id,session_revision,source_sha256,base_graph_sha256,selection_samples,sample_rate. The broker checks every binding and the configuration's alignment and rehashes the original source. This path reports actual candidate RMS change and omits residual comparison because baseline audio is absent. The native host rejects filtered audition bands. The absolute processing budget still applies.

Native audition resolves only the verified private UUID candidate, rehashes it, and uses the bounded file playback ring with an absolute timeline offset. It temporarily disables looping and raw gain matching, preserves graph parameters, and blocks export during preview. Dismissal restores the original snapshot, position and playback settings. Acceptance rechecks request/revision/source/graph/selection and preview hash, then performs one native parameter-history transaction. Delete history cancels work and removes preview/baseline files and redacted history; the currency ledger remains to prevent spending resets.

Broker admission permits at most two distinct requests globally and one per session, including pending persistence work; excess requests receive HTTP 429 `assistant_busy` and do not consume their request ID or invoke tools/providers. The native desktop still serializes its own requests. Redacted completed history retains at most 32 records, 8 MiB of record JSON, and 30 days, pruning oldest records at startup and after saves. The newest successful record is protected; an individually oversized record fails. These record limits exclude the separately preserved currency ledger. Each retained preview is additionally bounded by the per-request native frame/channel/rate limits. A completed request retains only its selected candidate; unused candidates are removed. Pruned records release matching UUID preview directories only after their host-created owner metadata matches the stored session hash, including after broker recreation. In-flight candidates have no completed history record to prune. History is local; no live calls run for retention.

Per-process replay/deletion metadata also has explicit lifetime admission limits: 4,096 distinct request IDs and 256 deleted-session tombstones. Both limits are checked before inserting new entries, and entries are never evicted. At capacity the broker fails closed (`request_identity_capacity` or `deleted_session_capacity`); an already-seen request remains a duplicate and an already-deleted session remains deleted. Busy rejections consume no ID. Deleting history does not reset either limit or the currency ledger. Recovery is an orderly broker restart after canceling/settling active work, rotating native session identities and authorized-session registration. A restart resets only process metadata; retained history still rejects its persisted duplicate IDs and the cumulative currency budget remains preserved. Library tests may supply smaller positive safe-integer limits; production defaults remain fixed.
