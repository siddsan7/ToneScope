# Release evidence contract v1

`release-manifest.schema.json` declares structural fields. `python evals/run.py release-check --manifest PATH` performs the executable semantic validation: files must exist and match SHA-256, suite/case status and commit must agree, all declared shipped requirements must have every coverage family represented by passing evidence, critical boundaries need validator cases, and required hardware/human/installation records and exact-commit reviewer approval must be present. Nonempty blocked checks fail. Synthetic passing suites cannot substitute for manual records. A validated manifest does not itself authorize publication or merge.

All file paths are resolved relative to the manifest (absolute paths are supported for local review). Bundle evidence with the release for durable review. Required suite references point at `run.json` and include SHA-256; case evidence paths resolve relative to that run. Manual qualification references point at structured records described in `qualification/README.md`. Signature and attestation use `{status: "verified", evidence: {path, sha256}}`, retaining the actual verifier output. Dependencies include name/version/SHA-256/license; toolchain and DSP generator include name/version. Baseline changes remain explicit records reviewed in dedicated baseline changes, never automatic golden overwrites.

The release checker verifies evidence structure, presence, hashes and consistency; it cannot establish whether an operator's real-world observations or reviewer identity are truthful. Human review is required. No release is currently qualified.
