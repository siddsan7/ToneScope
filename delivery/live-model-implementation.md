## Validated project lessons

- Windows atomic replacement can transiently fail with sharing errors. Retry only the same closed temporary payload, under the owned lock where applicable, with a fixed bound. Never delete the target or retry provider dispatch; preserve old complete state on permanent failure.
- Independent audio correctness does not prove provider provenance. Bind every credited candidate and patch to the actual verified service preview and request trace, and reconcile costs against durable request records.
- Compression needs fixed control values as evidence. Preserve them as read-only descriptors while independently restricting which parameter can change. A removed value and a read-only value have different meanings.
- Do not reconstruct a Node consent digest from JUCE-parsed doubles. Bind exact approved canonical bytes; require the Node host to validate the strict policy and exact canonical text before SDK import. Native typed consistency and numeric caps add defense but do not establish exact independent decimal identity.
- A failed provider result is distinct from a completed collector record. Apply fatal stop rules to the actual provider status/category and independent grade before admitting the next scheduled request; re-derive those rules when rebuilding a report.
- Use PowerShell7 for the existing Windows probe scripts and approved loopback context when the sandbox denies the real broker. Keep unchanged deadlines and assertions.

Live envelopes add bounded authorization, trace and scalar snapshots; offline shape/cost checks remain unchanged. Scalar descriptors are not full graph snapshots: native/collector must separately retain full `parametersToVar` snapshots, including topology/order/oversampling/crossovers. Native response cap remains64KiB.
