# Live evidence implementation contract v1

Implementation authorized 2026-10-26. Paid execution, publication, merge and deployment remain unauthorized. Existing offline corpora and numerical gates remain unchanged. This contract freezes infrastructure choices; model identity, prices and the transfer-task digest must be frozen in a separately approved experiment before collection.

## Step gates

Each step must pass its checks and independent review before its dependent step starts. A blocked check is not a pass. Save exact commands, exit codes and artifact hashes under `artifacts/live-model/`; summarize results in the working brain. Never infer a pass from a checklist tick.

| Step | Acceptance criteria and checks | Dependency |
|---|---|---|
| P0 | Protocol validator rejects changed limits, duplicate or missing stages and changed claim thresholds; frozen corpus loaders still pass; independent read-only design review has no unresolved blockers | None |
| P1 | Complete frozen schedule; unchanged/rules paired inputs; blocked, fault-injected and live provenance remain distinct; all attempted failures retained; independent audio negative probes fail their intended gates; collector cannot dispatch without consent and preflight | P0 |
| P2 | Request-keyed durable budget; idempotent reserve/settle; terminal usage immutable; cancel during load and late response regressions; cleanup despite persistence failure; actual subprocess kill and contention checks, three repeats per crash barrier; service typecheck, tests and build | P0 |
| P3 | Explicit private opt-in checked by native host and broker; linked identity-bound trace and full snapshots; level/compression preview, simulated accept, undo, stale/hash/cancel/restart tests; offline SDK-denial, startup, native and UI checks pass | P0, P2 |
| P4 | Integrated native CTest, service typecheck/tests/build, native-required Python evaluation tests, UI state, offline denial/startup and actual embedded workflows pass; source/runtime/binary hashes recorded; independent composition review passes | P1, P2, P3 |
| P4-live | Concrete model/provider and fresh authoritative pricing, approved text/measurements, total USD ceiling, budget identity and schedule digest; explicit user consent; complete attempt/accounting report; no automatic retries | P4 plus user consent |
| P5 | Independent read-only final audit of every scheduled denominator, provenance, accounting, audio oracles and claims; resolve findings and rerun affected gates | P4-live |
| P6 | Real human acceptance and undo, user architecture explanation and separate constraint exercise with failing-before/passing-after tests; report human/listening work pending until observed | P5 plus human participation |

P1 and P2 may run independently after P0. P3 waits for the accounting and consent interface to pass P2, to avoid implementing a moving trust boundary. All writers use isolated worktrees. Authors cannot be their sole reviewers.

## Shared contracts

- Protocol constants and claim thresholds: `evals/live_protocol.json`, validated by `evals/live_protocol.py`. This file grants no live authorization. Development tasks continue to use their existing locked files. Every freeze includes source, adapter/prompt, lockfile, binary and task digests. A changed identity invalidates dependent evidence.
- Consent: private host-owned file, strict versioned schema; experiment/budget identity, protocol/task digest, exact model/provider, verified price timestamp and metadata digest, rate ceilings, request/generation ceilings, USD ceiling and approved data classes. Missing, stale, mismatched or exhausted authorization fails before dispatch. Never persist credentials in consent or traces. Inherited environment variables alone cannot authorize native live mode.
- Desktop opt-in: explicit private evaluation configuration supplied by the host, visibly labeled live; host and service validate the same consent digest. Normal launch stays offline. Live envelopes must carry matching authorization/accounting identity and bounded finite cost; offline envelopes retain the zero-cost assertion. The model and server have no Apply capability.
- Trace: schema version, provenance (`blocked`, `fault-injected`, `live`), experiment/attempt/request/session IDs, monotonic sequence, event category, revision, source/graph/selection/preview bindings and consent digest. Export only allowlisted fields. Keep prompt text and local paths private. Events cover admission, reservation, generation start/end, measurements, render/compare, verified preview, terminal result, explicit user acceptance, apply and undo. Simulated acceptance is labeled. A live claim requires the same attempt across adapter and desktop.
- Accounting: versioned ledger with fixed budget identity and ceiling; request keys bind session/request and experiment. Reserve before dispatch. Repeating the same reservation is idempotent only when all bound inputs match. Settlement is idempotent with identical terminal usage and rejects conflicting usage. Interrupted/unknown requests retain their reservation. History deletion never deletes budget or request tombstones. Reject legacy/invalid ledgers rather than silently initializing a new budget. Atomic state replacement establishes process-kill recovery only. Do not claim power-loss durability.
- Dispatch: idempotent reservation is never permission to call the provider again. Persist a monotonic dispatch-authorized/started transition before invocation. An existing reserved, dispatched or terminal request key cannot obtain a second dispatch, including after restart or history deletion. An interrupted reservation remains encumbered even if the process died before actual dispatch; recovery can report uncertainty but cannot retry it. Identical settlement may replay without a provider call. Kill after reservation/pre-dispatch and during invocation, restart the same request and assert zero duplicate calls and no second reservation charge. A new attempt requires a distinct scheduled admission; no automatic retries.
- Count ceilings: admission atomically consumes a request slot and reserves its currency under the same durable budget lock. Every generation dispatch durably consumes a generation slot before invocation. Request and generation ceilings cover all processes and restarts sharing that budget identity. Identical reservation replay consumes no second slot and grants no new dispatch. Interrupted generations retain consumed slots. Test restart/contention at each ceiling; no in-memory counter can be the sole enforcement.
- Locks: store an owner identity; never steal a live owner's lock. Investigate safe dead-owner recovery with subprocess barriers. If death cannot be established, fail closed and document explicit recovery. Never refund unknown spend during recovery.
- Cancellation: register admission/controller before awaiting history. Race termination freezes exported usage; a late provider cannot mutate the terminal record or resurrect a proposal. Keep the full request reservation when authoritative usage is unknown. Always clear active/admission state and release previews even if ledger/history writes fail. Persist safe failure categories only.
- Collector: separate opt-in entry point; existing replay/offline runners stay unable to spend. No retries or provider switching. Hidden task answers never enter provider context. All scheduled attempts remain in the report, including blocked and invalid evidence; partial coverage cannot pass claim gates.

## Open external inputs

Exact model/provider, current prices and USD ceiling await a concrete user consent sheet after offline gates. Frozen transfer prompts belong to the evaluation owner; root sees category totals only until sealing. Human listening, recorded user acceptance and ownership assessment cannot be completed by automation. These dependencies do not block independent offline implementation.
