# Qualification evidence protocol

Status: **blocked — no hardware, human, installation or model qualification has been performed.** Synthetic CLI tests establish only their stated numerical and contract assertions.

Use a separate immutable JSON record per run: `schema_version: 1`, `record_id`, `kind` (`hardware`, `listening`, `accessibility`, `installation`), `status` (`pass`, `fail`, `blocked`), `operator`, `date` (UTC), `profile_id`, `observations`, `evidence` (file paths and SHA-256), `failures`, `limitations`. Keep raw logs with the record. Include every failure and aborted run. Passing records need measured observations and actual operator identity; a generated template is not evidence. Hash records into the release manifest.

Hardware: record CPU, RAM, Windows build, power policy, compiler/build flags, backend, physical interface and driver, sample rate, block size and graph. Test 44.1/48 kHz at 128/256/512 frames, and supported 96 kHz buffers. Release timing with separately measured instrumentation overhead must achieve p99.9 <50% and observed max <80% of the callback period over 30 minutes; record deadline misses separately. Run two-hour soak: zero app-caused underruns/crashes/unbounded queues and <10 MiB post-warmup memory growth. Qualify developer laptop and external interface as distinct profiles. Full-chain 4x is a stress graph. Instrument callback allocation/free/forbidden calls separately from timing. Measure physical loopback round-trip latency with method and uncertainty; callback period is not round-trip latency. No timing qualification from CI/VM.

Listening/usability: obtain consent, recruit initial 5–8 guitarists/audio practitioners, counterbalance tasks, match comparison levels and conceal presets. Compare microscope workflow to effects-knobs-plus-spectrum baseline. Tasks: locate harsh passage, reduce harshness preserving attack, explain compressor response. Record task completion count/time, wrong adjustments, confidence and comments. Proposed target >=80% completion and no unresolved critical task blocker; report counts and uncertainty, not population claims. A person must listen. Include participants with relevant access needs for accessibility claims; record keyboard, Narrator and scale task results separately. Keep private recordings outside public evidence and follow consent retention.

Installation: independent reviewer checks clean Windows install, launch/offline behavior, upgrade preserving sessions, rollback, recovery, uninstall, notices and licensing/signature verification. Retain actual OS/build and logs. Release requires the explicit reviewer decision at the exact commit plus complete hashed evidence.

AI: replay and live are separate gates. Locked original-source split, tool correctness and validation, grounded measurements, no-op/subjective/impossible tasks, adversarial content, service failures, cost/latency and human preferences require real evidence. Minimum proposed corpus is 240 tasks (120 development / 60 validation / 60 locked) plus 60 adversarial/failure cases. Approved credentials, budget and locked corpus are prerequisites; unavailable is blocked. Never treat a mock as live evaluation.
